# Squidify — виджет Spotify для OBS и Windows

Squidify — бесплатная альтернатива платным виджетам «Сейчас играет» (вроде Amuse). Каждый пользователь регистрируется на сайте, подключает свой Spotify, настраивает дизайн в визуальном редакторе и получает персональную ссылку для OBS Studio. Тот же виджет можно открыть в прозрачном окне Windows поверх других окон.

> Squidify — независимый проект. Он не связан со Spotify AB, не одобрен и не поддерживается Spotify. Spotify — товарный знак Spotify AB.

## Возможности

- **Аккаунты.** Регистрация, вход, выход, восстановление пароля, смена пароля, удаление аккаунта. Данные пользователей изолированы через Row Level Security.
- **Подключение Spotify.** Authorization Code Flow with PKCE, без Client Secret. У каждого пользователя свой Client ID, есть режим общего Client ID. Refresh-токены хранятся на сервере в зашифрованном виде (AES-256-GCM).
- **Редактор с предпросмотром.** 6 макетов: горизонтальный, вертикальный, компактный, только текст, крупная обложка, полоса прогресса. Настраиваются размеры, отступы, выравнивание, 22 шрифта (отдельный шрифт для исполнителей), размеры и цвета текста, эффекты текста (градиент, бегущая радуга, неон, контур), своя подпись над названием, цветной или градиентный фон, прозрачность, размытие, рамка (стили линии, пульсирующее свечение, бегущая радуга), тени, перетекающий градиент фона, размер и сторона обложки, 7 стилей прогресс-бара, **визуализатор** (столбики, волна, точки, эквалайзер, «волна трека» как в SoundCloud) вместо полосы прогресса, **две свои картинки или GIF** по https-ссылке (без фона, где угодно в карточке, с условием «когда видна»), 9 анимаций смены трека, постоянная анимация карточки и прокрутка длинных названий. Визуализатор — анимация, а не реальный спектр: Spotify не отдаёт приложениям звук трека. Отдельно настраивается поведение без музыки и на паузе.
- **Пресеты.** 14 готовых пресетов и неограниченное число своих (до 50 на аккаунт). Несколько виджетов на аккаунт (до 20).
- **Демо-трек.** Предпросмотр работает и без подключённого Spotify.
- **OBS.** Отдельная публичная ссылка на каждый виджет с прозрачным фоном. В ссылке длинный случайный токен только для чтения, его можно пересоздать. Изменения дизайна применяются к ссылке автоматически.
- **Окно Windows (Electron).** Прозрачное окно без рамки поверх всех окон. Перемещается мышью, размер меняется за уголок, положение и размер запоминаются. Есть фиксация положения, сквозные клики, трей, горячая клавиша, автозапуск и открытие виджета с сайта одной кнопкой (`squidify://`).
- **Демо-режим.** Без ключей Supabase сайт запускается полностью, данные хранятся в браузере.

## Архитектура

```
┌──────────────────────┐   supabase-js (RLS)   ┌────────────────────────────┐
│ Сайт (GitHub Pages)  │──────────────────────▶│ Supabase                   │
│ React + TS + Vite    │                       │  Auth · PostgreSQL + RLS   │
│  • редактор          │  Edge Functions       │  Edge Functions (Deno):    │
│  • /w/#токен (OBS)   │──────────────────────▶│   spotify-auth             │──▶ Spotify Accounts (PKCE)
└──────────────────────┘                       │   widget-feed (публичный)  │──▶ Spotify Web API
          ▲                                    │   account-delete           │
          │ iframe                             └────────────────────────────┘
┌──────────────────────┐
│ Squidify Desktop     │  Electron: прозрачное окно, трей, горячая клавиша
└──────────────────────┘
```

| Папка | Что внутри |
| --- | --- |
| `web/` | Сайт: React 19, TypeScript, Vite, react-router. Страница виджета `web/src/pages/WidgetPage.tsx`, рендер `web/src/widget/` |
| `supabase/migrations/` | SQL-схема: таблицы, RLS, права на столбцы, функции |
| `supabase/functions/` | Edge Functions: `spotify-auth`, `widget-feed`, `account-delete` и общий код в `_shared/` |
| `supabase/tests/` | Проверка миграций и RLS на чистом PostgreSQL |
| `desktop/` | Приложение Electron для Windows |
| `.github/workflows/` | CI, деплой на GitHub Pages, сборка Windows-приложения, деплой Supabase |

### Как работает виджет

1. OBS открывает `https://<user>.github.io/<repo>/w/#<токен>`. Токен (64 hex-символа, 256 бит) находится во фрагменте `#`, поэтому не уходит на сервер GitHub Pages и не попадает в Referer.
2. Страница отправляет токен в заголовке `X-Widget-Token` функции `widget-feed`. Функция находит виджет и возвращает конфигурацию и текущий трек. Email, id пользователя, имя аккаунта Spotify и токены Spotify она не возвращает.
3. Все виджеты пользователя читают общий кеш `playback_cache` (TTL 4 секунды). К Spotify обращается только запрос, захвативший блокировку `acquire_playback_lock`. Поэтому десять открытых виджетов создают те же 1 запрос в 4–5 секунд, что и один.
4. Интервал опроса задаёт сервер: около 5 с во время воспроизведения (и сразу после окончания трека), 10 с на паузе, 15 с без музыки, 60 с без подключения. При 429 соблюдается `Retry-After`, при сетевых ошибках интервал растёт экспоненциально. Прогресс между запросами досчитывается в браузере.
5. Конфигурация передаётся только при изменении версии (`X-Config-Version`), поэтому изменения из редактора доходят до OBS за один цикл опроса.

## Важно про Spotify

Требования Spotify проверены по официальной документации на октябрь 2026 года:

- **Development Mode** (с [февраля 2026](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide)): не больше 5 пользователей на одно приложение, и у владельца приложения должна быть активная подписка **Spotify Premium**. Расширенная квота выдаётся только организациям.
- Поэтому основной режим Squidify — **собственный Client ID**: каждый пользователь создаёт своё бесплатное приложение в Spotify for Developers (одному разработчику доступно до 25 Client ID) и подключает его. Для этого у пользователя должен быть Premium.
- **Общий Client ID** включается секретом `SPOTIFY_SHARED_CLIENT_ID`. Используйте его, если приложение получило расширенную квоту или всех пользователей (до 5) добавили вручную в User Management.
- **Redirect URI** ([правила](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri)): только HTTPS, кроме loopback-адресов `http://127.0.0.1:PORT` и `http://[::1]:PORT`. `localhost` запрещён. Адрес должен совпадать в точности, включая завершающий `/`.
- **Разрешения:** только `user-read-currently-playing`.
- **Implicit Grant** устарел, а Client Secret во фронтенде хранить нельзя. Поэтому используется PKCE: обмен кода и обновление токена идут на сервере (Edge Function) без секрета.
- **Правила оформления** ([Design guidelines](https://developer.spotify.com/documentation/design)): рядом с метаданными всегда виден значок Spotify (не меньше 21 px, не поверх обложки). Обложка не обрезается, не размывается и не анимируется, её скругление не больше 8 px. Трек, исполнитель и альбом ведут ссылками на Spotify, для кнопки доступны только тексты «OPEN / PLAY ON / LISTEN ON SPOTIFY». Длинные названия прокручиваются, чтобы текст можно было прочитать целиком.
- Squidify не скачивает, не воспроизводит и не ретранслирует аудио, не хранит историю прослушивания и не синхронизирует музыку с видео.

## Быстрый старт: демо-режим

Нужен Node.js 20+ (рекомендуется 22).

```bash
npm ci
npm run dev
```

Откройте <http://127.0.0.1:5173/>. Без настроек Supabase сайт работает в демо-режиме: виджеты и пресеты хранятся в localStorage, вместо Spotify показывается демо-трек. Ссылку для OBS тоже можно проверить: в демо-режиме конфигурация зашита в ссылку.

## Полная установка

### 1. Проект Supabase

1. Создайте проект на <https://supabase.com/dashboard> (бесплатного тарифа достаточно).
2. Запишите **Project URL** и **anon / publishable key** (Project Settings → API). Они публичные и попадут в сайт. **service_role / secret key** никуда не копируйте: функции получают его автоматически.
3. Примените миграции одним из способов:
   - через [Supabase CLI](https://supabase.com/docs/guides/cli):
     ```bash
     npx supabase login
     npx supabase link --project-ref <PROJECT_REF>
     npx supabase db push
     ```
   - или откройте **SQL Editor** и выполните содержимое `supabase/migrations/20261029000000_init.sql`.
4. **Authentication → URL Configuration:**
   - *Site URL*: `https://<user>.github.io/<repo>/`
   - *Redirect URLs*: `https://<user>.github.io/<repo>/**` и для локальной разработки `http://127.0.0.1:5173/**`
5. **Authentication → Providers → Email:** включите Email и подтверждение email (Confirm email). Встроенная почта Supabase отправляет мало писем в час, поэтому для реального использования подключите свой SMTP (Authentication → Emails → SMTP Settings).
6. Сгенерируйте ключ шифрования токенов:
   ```bash
   openssl rand -base64 32
   ```
   Храните его надёжно. Если ключ потерян, всем придётся переподключить Spotify.
7. Задайте секреты функций. Скопируйте `supabase/functions/.env.example` в `supabase/functions/.env` (этот файл не коммитится), заполните его и выполните:
   ```bash
   npx supabase secrets set --env-file supabase/functions/.env
   ```
   | Секрет | Значение |
   | --- | --- |
   | `TOKEN_ENCRYPTION_KEY` | ключ из шага 6 |
   | `ALLOWED_REDIRECT_URIS` | `https://<user>.github.io/<repo>/callback/spotify/` (через запятую можно добавить `http://127.0.0.1:5173/callback/spotify/`) |
   | `ALLOWED_ORIGINS` | необязательно: `https://<user>.github.io,http://127.0.0.1:5173` |
   | `SPOTIFY_SHARED_CLIENT_ID` | необязательно: общий Client ID |
8. Задеплойте функции. Настройки `verify_jwt = false` берутся из `supabase/config.toml`: функции сами проверяют JWT пользователя, а `widget-feed` публичная.
   ```bash
   npx supabase functions deploy
   ```

Миграции и функции также можно деплоить из GitHub Actions: workflow **Deploy Supabase** запускается вручную и требует секретов `SUPABASE_ACCESS_TOKEN`, `SUPABASE_DB_PASSWORD` и переменной `SUPABASE_PROJECT_REF`.

### 2. Spotify Developer Dashboard

Эти шаги проходит **каждый пользователь** в режиме собственного Client ID. На сайте они повторяются на странице «Spotify» с кнопкой копирования Redirect URI.

1. Откройте <https://developer.spotify.com/dashboard> и нажмите **Create app**.
2. Название и описание любые. В **Redirect URIs** добавьте точный адрес: `https://<user>.github.io/<repo>/callback/spotify/`. Для локальной разработки добавьте ещё `http://127.0.0.1:5173/callback/spotify/`.
3. В **Which API/SDKs are you planning to use?** отметьте **Web API**, примите условия и сохраните.
4. **Settings → User Management:** добавьте свой аккаунт Spotify (имя и email). Без этого в Development Mode Spotify возвращает 403.
5. Скопируйте **Client ID** и вставьте его на странице «Spotify» сайта. Client Secret не нужен.

### 3. Локальный запуск с Supabase

```bash
cp web/.env.example web/.env.local   # заполните VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY
npm run dev                          # http://127.0.0.1:5173
```

Сайт должен открываться именно по `127.0.0.1`, а не `localhost`: Spotify не принимает `localhost` в Redirect URI. Добавьте `http://127.0.0.1:5173/callback/spotify/` в `ALLOWED_REDIRECT_URIS` и в Spotify Dashboard.

Полностью локальный Supabase (нужен Docker):

```bash
npx supabase start                                       # БД, Auth, Studio
npx supabase functions serve --env-file supabase/functions/.env
```

Для локального Supabase в `web/.env.local` укажите `VITE_SUPABASE_URL=http://127.0.0.1:54321` и anon key из вывода `supabase start`.

### 4. Публикация на GitHub Pages

1. **Settings → Pages → Build and deployment → Source:** выберите **GitHub Actions**.
2. **Settings → Secrets and variables → Actions → Variables** добавьте:
   - `SUPABASE_URL` — Project URL;
   - `SUPABASE_ANON_KEY` — anon/publishable key (публичный, поэтому это переменная, а не секрет);
   - необязательно `CONTACT_EMAIL` для политики конфиденциальности;
   - необязательно `PAGES_BASE_PATH=/`, если сайт живёт на своём домене или в репозитории `<user>.github.io`.
3. Запушьте в `main`. Workflow **Deploy site to GitHub Pages** соберёт сайт с базовым путём `/<repo>/` и опубликует его.

Прямые ссылки работают на статическом хостинге: после сборки `web/scripts/spa-fallback.mjs` кладёт копию `index.html` в папку каждого маршрута (`w/`, `callback/spotify/`, `app/`, …) и в `404.html`. Поэтому ссылка для OBS и Redirect URI отдаются с кодом 200.

### 5. Приложение для Windows

Готовые сборки публикуются в **Releases** при пуше тега `desktop-v*`:

```bash
git tag desktop-v1.0.0 && git push origin desktop-v1.0.0
```

Workflow **Desktop release (Windows)** соберёт установщик NSIS и portable-версию. Собрать вручную на Windows:

```bash
npm ci
npm run dist -w desktop      # результат в desktop/release/
```

Запуск из исходников (Windows, macOS или Linux): `npm start -w desktop`.

Как пользоваться:

- Нажмите «В окне Windows» в списке виджетов на сайте (откроется `squidify://open?url=…`, приложение спросит подтверждение) или вставьте ссылку виджета в окне настроек.
- Перетащите виджет мышью. Размер меняется за уголок справа внизу или в настройках, по умолчанию окно подгоняется под виджет.
- Меню трея: показать/скрыть, «Поверх всех окон», «Зафиксировать положение», «Пропускать клики сквозь виджет», обновить, вернуть окно на экран, настройки, выход.
- Горячая клавиша по умолчанию — `Ctrl+Alt+S`, её можно поменять в настройках.
- Настройки и положение окна хранятся в `%APPDATA%\Squidify\settings.json`.

Безопасность: окно загружает локальную оболочку (`desktop/static/shell.html`) со строгим CSP, а страница виджета открывается во вложенном `iframe` с атрибутом `sandbox`. У удалённой страницы нет preload и доступа к Node.js или Electron. Для всех окон включены `contextIsolation`, `sandbox`, `webSecurity`, а `nodeIntegration` выключен. Разрешения (камера, микрофон, уведомления и т. п.) запрещены. Переходы фрейма возможны только в пределах origin виджета, новые окна запрещены, ссылки на `open.spotify.com` открываются в системном браузере. IPC проверяет отправителя.

## Безопасность и данные

- **RLS** включён на всех таблицах. Пользователь видит и меняет только свои виджеты, пресеты и статус подключения. Права на столбцы не дают клиенту задать `user_id` или `public_token`.
- **Секреты** (`spotify_tokens`, `oauth_states`, `playback_cache`) недоступны ролям `anon` и `authenticated`, к ним обращаются только Edge Functions с service_role.
- **Токены Spotify** шифруются AES-256-GCM с AAD, привязанным к пользователю, поэтому шифротекст одного пользователя нельзя подставить другому. В браузер и в ссылку виджета токены не попадают.
- **OAuth state** одноразовый, живёт 10 минут и привязан к пользователю. В базе хранится его SHA-256, а `code_verifier` хранится в зашифрованном виде. State дополнительно сверяется в той же вкладке браузера через sessionStorage.
- **Redirect URI** проверяется по списку `ALLOWED_REDIRECT_URIS`.
- **Отключение Spotify** удаляет токены, кеш, OAuth state и запись о подключении. **Удаление аккаунта** удаляет всё, включая пользователя Auth. Если Spotify отзывает доступ (`invalid_grant`), токены удаляются автоматически.
- **История прослушивания не хранится:** в кеше лежит только последнее состояние, оно перезаписывается.
- **Конфигурация виджета** нормализуется (`normalizeConfig`) при сохранении и при отображении: цвета, шрифты и числа проверяются по белым спискам. Метаданные выводятся только как текст, ссылки и картинки принимаются только с доменов Spotify.

Политика конфиденциальности находится на сайте по адресу `/privacy` (`web/src/pages/Privacy.tsx`).

## Лимиты и нагрузка

- Один активный виджет во время воспроизведения делает около 720 вызовов `widget-feed` в час. Бесплатный тариф Supabase включает 500 000 вызовов Edge Functions в месяц, этого хватает примерно на 690 часов воспроизведения с одним открытым виджетом. В фоновой вкладке опрос замедляется до 30 с.
- К Spotify уходит не больше одного запроса на пользователя за 4 секунды, сколько бы виджетов ни было открыто.
- Лимиты аккаунта: 20 виджетов, 50 пресетов, конфигурация до 32 КБ.

## Решение проблем

| Симптом | Причина и решение |
| --- | --- |
| `INVALID_CLIENT: Invalid redirect URI` на странице Spotify | Redirect URI в Spotify Dashboard не совпадает с адресом на странице «Spotify» сайта. Скопируйте его кнопкой, проверьте завершающий `/` |
| «Этот Redirect URI не разрешён на сервере» | Добавьте адрес в секрет `ALLOWED_REDIRECT_URIS` и повторите `supabase secrets set` |
| Виджет показывает ошибку 403 | Аккаунт не добавлен в User Management приложения Spotify или у владельца приложения нет Premium |
| «Доступ к Spotify истёк» | Доступ отозван на spotify.com/account/apps или Client ID удалён. Переподключите Spotify |
| Письма подтверждения не приходят | Встроенная почта Supabase ограничена, подключите SMTP |
| В OBS виджет обрезан | Увеличьте размер Browser Source до рекомендуемого (указан в редакторе) |
| После деплоя открывается пустая страница | Проверьте `VITE_BASE_PATH`: для `https://user.github.io/repo/` он равен `/repo/` |
